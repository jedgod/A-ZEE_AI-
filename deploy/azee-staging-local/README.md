# azee-staging-local

LOCAL staging for A-Zee + AZTrade on Docker with PostgreSQL 16. **Not production.** Live trading stays disabled; no production flags or credentials are used.

## Status (read first)
| Part | Verified how |
|---|---|
| PKI + automated rotation/revocation (`scripts/staging/pki.mjs`) | tested natively (`tests/staging-listener.test.ts`) |
| mTLS listener launcher (`scripts/introspect-listener.mjs`) | tested natively, including as a real process |
| PostgreSQL 16 databases/roles (`scripts/staging/db-bootstrap.mjs`), AZTrade schema applier | tested natively on PG16 (`tests/staging-db.test.ts`) |
| Compose topology + gateway allowlist | **static** tests only (`tests/staging-compose.test.ts`) |
| Container builds, running stack, runtime network isolation, restart/recovery | **NOT RUN** (Docker engine was not running on the build machine) |

## Topology
```
client (browser / Android)  ->  gateway (nginx, HTTPS :8443, edge network, DEFAULT DENY allowlist)
                                   |
                                  app (Next.js, edge + private)  ---mTLS--->  introspect (private only)  ---> db (azee_staging)
                                                                              aztrade-api (private only) ---mTLS--> introspect
                                                                              db: postgres:16, private only, separate databases/roles
```
- `private` is a Docker `internal` network: no route outside. Only `gateway` publishes a port (loopback by default).
- `/api/aztrade/introspect|ai|jwks`, `/api/admin`, `/api/operations`, `/api/staff`, webhooks, the DB and the AZTrade API are never routed.
- Docker networking alone is not proof of anything beyond this host; run `verify-isolation.ps1` against the running stack.

## Ports (this machine, checked 2026-11-09)
In use before this stack: 8080 (Apache httpd), 11434 (Ollama). This stack uses **8443** (gateway, published) and nothing else on the host. Internal ports (not published): app 3000, aztrade-api 3001, introspect 8443, db 5432.

## Databases and roles
`azee_staging` (owner `azee_owner`, runtime `azee_app`) and `aztrade_staging` (owner `aztrade_owner`, runtime `aztrade_app`, `aztrade_provisioner`, `aztrade_marketdata`). No role is superuser or BYPASSRLS; PUBLIC has no CONNECT; every runtime role can connect to its own database only; runtime roles cannot create objects.

## Secrets and certificates (paths only)
- Secrets: `secrets-staging/<NAME>` (generated by `node scripts/staging/make-secrets.mjs`, git-ignored, never overwritten). Mounted at `/run/secrets/<NAME>`; read through `lib/secrets` (file provider) or exported by `with-secrets.sh`.
- PKI: `secrets-staging/pki/ca/` (CA key; only `pki-rotate`/the host may see it) and `secrets-staging/pki/live/<identity>/{cert.pem,key.pem,ca.pem,ca.crl}`; each service mounts only its own identity directory, read-only.
- Rotation: `node scripts/staging/pki.mjs rotate` (or `watch`) reissues certificates under 40% lifetime and refreshes the CRL every run (CRL validity is 7 days: run at least daily). `revoke <identity>` revokes + republishes; the listener reloads within 30 s.

## Bring-up
```
.\deploy\azee-staging-local\up.ps1                 # loopback only
.\deploy\azee-staging-local\up.ps1 -LanIp 192.168.x.y   # also publish on the LAN for a physical phone (adds the IP to the gateway certificate)
.\deploy\azee-staging-local\verify-isolation.ps1
```
**Memory:** Docker Desktop's VM needs roughly 2-3 GB plus the Next.js build (~2 GB peak). Close other applications first on a memory-constrained machine.

## Known gaps
- AI provider keys are not configured for staging: AI replies fail closed until one is (a local Ollama on the host is an option; not wired).
- The A-Zee trade UI does not yet proxy to the AZTrade API; the API is reachable only inside the private network.
- Android debug builds need the staging CA trusted by the app (network security config for debug builds) in addition to the device trust store.
- A-Zee code still reads `DATABASE_URL` directly (exported by `with-secrets.sh`), not through `lib/secrets`.
- Production: NO-GO.
